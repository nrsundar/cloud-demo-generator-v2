## Context

A senior SA's value comes from internal knowledge: previous demo packages, customer architectures, AWS reference patterns, partner playbooks, recent feature launches. Today's DemoForge agent has none of that — it reasons from first principles every time.

P3.1 turns that internal knowledge into context the agent can pull at the right moment. Retrieval-Augmented Generation (RAG) is invoked as a *deliberate step* via tools — not as a black-box prompt prefix. The agent decides when to search and what to do with the results.

This is the differentiator: a new SA's first demo measurably benefits from every demo every other SA has built.

## Design

### Storage

Per [ADR-0005](../../decisions/0005-pgvector-on-neon.md), the vector store is `pgvector` on Neon. Required:

- Verify `CREATE EXTENSION vector;` succeeds on the Neon database.
- Drizzle custom column type for `vector(N)`.

### Schema additions

```ts
// shared/schema.ts

import { customType } from "drizzle-orm/pg-core";

const vector = (dim: number) => customType<{ data: number[]; driverData: string }>({
  dataType() { return `vector(${dim})`; },
  toDriver(value) { return `[${value.join(",")}]`; },
  fromDriver(value) { return JSON.parse(value); },
});

export const corpusDocuments = pgTable("corpus_documents", {
  id: serial("id").primaryKey(),
  source: text("source").notNull(),                   // 'demo' | 'aws_docs' | 'playbook' | 'customer_note'
  externalId: text("external_id"),                    // e.g. demoRequest.id, doc URL
  title: text("title").notNull(),
  uri: text("uri"),
  ownerId: text("owner_id"),
  teamId: text("team_id"),
  visibility: text("visibility").notNull().default("org"),  // 'private' | 'team' | 'org'
  metadata: json("metadata"),                         // { industry, database, extension, ... }
  ingestedAt: timestamp("ingested_at").defaultNow().notNull(),
  updatedAt: timestamp("updated_at").defaultNow().notNull(),
});

export const corpusChunks = pgTable("corpus_chunks", {
  id: serial("id").primaryKey(),
  documentId: integer("document_id").references(() => corpusDocuments.id).notNull(),
  chunkIndex: integer("chunk_index").notNull(),
  content: text("content").notNull(),
  embedding: vector(1024)("embedding"),               // Titan v2 = 1024 dims
  tokens: integer("tokens").notNull(),
  metadata: json("metadata"),
});
```

Indexes:

- `corpus_chunks` HNSW or IVFFlat on `embedding` (`USING hnsw (embedding vector_cosine_ops)`). Created via Drizzle migration with `sql\`...\`` raw — still inside Drizzle API surface, complies with constraint 8.
- `corpus_chunks` GIN on a `tsvector` derived column for BM25-style lexical search.
- `corpus_documents (source, visibility)` for filter pruning.

### Retrieval flow

```
agent calls tool: searchPriorDemos({ query, filters })
      │
      ▼
1. Embed query (Bedrock Titan v2; cache via P2.3 embedding cache)
2. Vector search:    SELECT * FROM corpus_chunks
                     WHERE document.visibility ∈ visibleTo(principal)
                     ORDER BY embedding <=> $queryEmbedding
                     LIMIT 50
3. Lexical search:   SELECT * FROM corpus_chunks
                     WHERE tsvector @@ plainto_tsquery($query)
                     LIMIT 50
4. Hybrid blend:     RRF (Reciprocal Rank Fusion), top 10
5. Per-document filter (one chunk per doc, max 5 docs)
6. Return:           [{ documentId, title, snippet, similarity, source, citation }]
```

ACL is enforced at step 2 by joining against `corpus_documents.visibility` and using `visibleTo(principal)` from P1.6. There is no "unfiltered" path — the SQL query simply does not return rows the principal cannot see.

### Re-ranking

Deferred to v2. Initial blend is RRF on raw vector + BM25. Once we have eval data showing where retrieval misses, decide between:

- LLM re-ranker (one Bedrock call to rank top 50 → top 10).
- Cross-encoder model (would need a new dep — gated by ADR-0011 evolution).

For v1, RRF is good enough.

### Initial corpora

| Source | Volume | Ingestion |
|---|---|---|
| Prior demo packages | ~50 today, growing | One-time backfill from `demo_requests` + `repositories`; ongoing on every successful generation. |
| AWS docs (PostgreSQL/RDS pages) | ~500 pages | One-time scrape; refresh quarterly. |
| Internal playbooks | ~20 today | Manual upload via admin UI. |
| Customer notes | per-customer | Out of scope for v1; ingestion path exists but no source connector yet. |

### Ingestion pipeline

```
server/rag/
  ingest.ts                  # CLI: ingestDocument(source, content, metadata)
  chunk.ts                   # text → chunks (sentence-aware, 500 tokens, 50-token overlap)
  embed.ts                   # Bedrock Titan v2 calls; uses embedding cache
  index.ts                   # writes corpus_documents + corpus_chunks
```

Chunking strategy: sentence-aware splitter, 500 tokens per chunk, 50-token overlap. Configurable per source.

### New tools

| Tool | Description |
|---|---|
| `searchPriorDemos` | Replaces the placeholder from P1.2 with real RAG. |
| `searchAwsDocs` | RAG over the AWS docs corpus. |
| `searchPlaybooks` | RAG over internal playbook corpus. |
| `lookupCustomerAccount` | Stub remains; activated when a customer connector exists. |

All four enforce ACL via `visibleTo(principal)`.

### Citation

Tools return `{ snippets: [{ documentId, title, source, content, uri? }] }`. The agent's system prompt instructs it to cite — components emitted as a result of retrieval reference the snippet IDs. Add a new `GenNode` type `RagCitation`:

```ts
| { type: "RagCitation"; sources: { title: string; source: string; uri?: string }[] }
```

This is the 18th `GenNode` type that resolves the discrepancy noted in P1.4. (Constraint 21 is updated as part of P3.1, gated by [ADR-0010](../../decisions/0010-gennode-gated-process.md).)

### Drift / freshness

- Demo packages re-embedded on every update.
- AWS docs refreshed quarterly via CI job.
- Stale-document detector: any `corpus_documents` row whose `updatedAt` is more than 180 days old is flagged in the admin UI for review.

## Constraint compliance

| Constraint | How this complies |
|---|---|
| 5 — no new dependencies | pgvector is a Postgres extension, not an npm dep. Drizzle custom column type is in-house. |
| 8 — Drizzle + Neon | New tables via Drizzle. Index creation uses `sql\`...\`` inside a Drizzle migration — still Drizzle API. |
| 9 — Bedrock only | Embeddings via Bedrock Titan v2 ([ADR-0004](../../decisions/0004-bedrock-embeddings-allowed.md)). |
| 17 — no secrets in frontend | Retrieval lives server-side; frontend sees only sanitized snippets. |
| 21 — fixed `GenNode` types | New `RagCitation` type added via the gated process in [ADR-0010](../../decisions/0010-gennode-gated-process.md). |

## Sequencing and dependencies

- **Before:** P1.2, P1.6 (ACL), P2.1 (trace retrieval to debug recall), P2.3 (embedding cache).
- **After:** P3.4 (drift detection notices retrieval-quality drops).

## Exit criteria

1. `pgvector` extension active on Neon (verified via `SELECT * FROM pg_extension WHERE extname = 'vector';`).
2. Initial corpus ingested: ≥ 50 demos + ≥ 500 AWS doc pages + ≥ 20 playbooks.
3. Eval subset "prior-demo-required" — fixtures explicitly designed to need RAG context — improves by ≥ 20 points (tier 2 score) vs. the no-RAG baseline.
4. ACL test — user A's private demo never appears in user B's retrieval results.
5. Latency budget — retrieval (steps 1–6 above) completes in ≤ 800ms p95.
6. `RagCitation` component renders correctly in `/admin/genui-gallery` (P3.3).

## Risks

| Risk | Mitigation |
|---|---|
| pgvector not enabled on the current Neon plan | Verify in week 1; switch plans if needed. Prerequisite documented in this file. |
| Titan v2 unavailable in `us-east-2` | Fall back to Cohere Embed via Bedrock; both are 1024-dim. |
| Hybrid blend (RRF) underperforms a re-ranker | Track recall@10 in eval; gate re-ranker work on observed gap. |
| Customer notes ingestion exposes PII to wider audience | Customer-note source is out of scope for v1 specifically because of this; defer until ACL story is proven on lower-stakes corpora. |
| HNSW index build time on 100K chunks | Run as a background DDL during off-hours; first build may take 30+ minutes. |
| Embedding cost over time | P2.3 embedding cache makes the steady state ~zero; first ingest is the only spend. |

## Out of scope

- Re-ranking (deferred to v2).
- Multi-modal embeddings (text only for v1).
- Customer-note ingestion connector (deferred).
- Cross-tenant retrieval ("show me what other AEs did for similar customers") — explicitly out per ACL design.
