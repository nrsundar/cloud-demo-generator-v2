# P3.2 — Multi-Model Routing

| | |

| **Effort** | 1 week (only if gate opens) |
| **Owner** | TBD |

## Context

Different stages of the agent loop have different needs:

- **Conversation / planning** — strong frontier model.
- **Spec-field extraction** ("parse this user prompt into a structured snapshot") — fast, cheap model. Routinely uses < 200 output tokens.
- **Eval LLM-judge** — separate model from the evaluatee to remove same-model bias.
- **Embeddings** — already a different model (Titan v2 per [ADR-0004](../../decisions/0004-bedrock-embeddings-allowed.md)).

P3.2 introduces a model gateway that abstracts provider/model selection inside Bedrock. **It does not relax constraint 9** — we stay on Bedrock. The question is: do we stay on Opus 4.6 only, or are other Anthropic-family models inside Bedrock allowed?

## Gate

This phase item is **paused** until [ADR-0011](../../decisions/0011-multi-model-routing.md) is decided. The ADR has two options:

- **Option A (strict):** Constraint 9 reads as "Opus 4.6 only." P3.2 is dropped. Cost story is "Opus everywhere with aggressive caching."
- **Option B (relaxed):** Constraint 9 reads as "Bedrock + Anthropic family, Opus 4.6 default." P3.2 proceeds with the design below.

The cost delta between A and B is substantial (~2x at scale). The owner decision is recorded in ADR-0011.

## Design (only if Option B selected)

### Model gateway

```
server/agent/modelGateway.ts
```

Single function:

```ts
export interface ModelRequest {
  task: "orchestrator" | "extractor" | "judge";
  messages: Message[];
  tools?: ToolSpec[];
  maxTokens?: number;
  cacheControl?: boolean;
}

export async function invokeModel(req: ModelRequest): Promise<ModelResponse>;
```

Internal route table:

```ts
const ROUTE: Record<ModelRequest["task"], { primary: string; fallback?: string }> = {
  orchestrator: { primary: "us.anthropic.claude-opus-4-6-v1" },
  extractor:    { primary: "us.anthropic.claude-haiku-4-5-20251001",
                  fallback: "us.anthropic.claude-opus-4-6-v1" },
  judge:        { primary: "us.anthropic.claude-sonnet-4-6",
                  fallback: "us.anthropic.claude-opus-4-6-v1" },
};
```

Fallback triggers on:

- Bedrock throttling (HTTP 429 / `ThrottlingException`).
- Region-level model unavailability (HTTP 503 / `ModelNotReadyException`).

The fallback is logged in `agent_spans.modelId` so the trace shows which model actually ran.

### Where each model is used

- **Orchestrator (Opus 4.6)** — the agent loop's main model invocations. Tool orchestration, planning, final envelope generation. Unchanged from Phase 1.
- **Extractor (Haiku)** — invoked by a new internal helper `extractSpecFromText(prompt)` called once at the start of a session. Today the orchestrator does this implicitly inside its first turn, costing Opus tokens. Moving it to Haiku saves ~2K input tokens per session.
- **Judge (Sonnet)** — invoked only by the eval harness (P2.4), never by user-facing flows. Eliminates same-model bias.

### Cost accounting impact

P2.1's `PRICING` table grows to include Haiku and Sonnet:

```ts
"us.anthropic.claude-opus-4-6-v1":     { in: 15.00, out: 75.00 },
"us.anthropic.claude-sonnet-4-6":      { in: 3.00,  out: 15.00 },
"us.anthropic.claude-haiku-4-5-20251001": { in: 1.00,  out: 5.00 },
```

`agent_spans.modelId` already records which model ran; the cost rollup just works.

### Eval confirmation

Before flipping the orchestrator route to anything other than Opus 4.6 (we don't, in this design), the harness from P2.4 must show:

- Extractor: spec accuracy ≥ 95% match against Opus baseline on a 100-prompt corpus.
- Judge: rubric scores correlate with human-rated baseline (Spearman ≥ 0.8).

If extractor falls below the threshold, fall back to Opus for extraction; the gateway makes this a one-line config change.

### Configuration

Route table lives in `server/agent/modelGateway.ts` as a const. Changing it is a code change → MR → eval gate. No runtime configuration; this is intentional — model routing changes should be reviewed.

## Exit criteria (only if Option B)

1. `modelGateway.invokeModel()` is the only path to Bedrock model invocations (grep for `InvokeModelCommand` returns one match — inside the gateway).
2. Eval harness shows extractor parity ≥ 95% with Opus baseline.
3. Cost-per-conversation drops by ≥ 40% on the eval set vs. P2.3 baseline.
4. Fallback test: synthetic 429 from Haiku triggers Opus fallback and the trace records `modelId = "us.anthropic.claude-opus-4-6-v1"` for that span.

## Risks (only if Option B)

| Risk | Mitigation |
|---|---|
| Haiku extractor degrades on edge prompts | Eval gate. Fallback to Opus if accuracy drops below threshold per release. |
| Sonnet judge unavailable for extended periods | Fallback to Opus, with a documented same-model-bias caveat in eval reports. |
| Constraint 9 ambiguity creates audit confusion | ADR-0011 records the explicit interpretation. Bind any change to a CONSTRAINTS.md update. |
| Pricing for new models not in `PRICING` table | CI lint checks: every `agent_spans.modelId` value must appear in `PRICING` or the run fails. |

## Out of scope

- Non-Anthropic models on Bedrock (e.g. Cohere Command, Llama). Even in Option B, we stay Anthropic-family.
- Non-Bedrock providers (OpenAI, Anthropic direct). Hard-blocked by constraint 9.
- Per-tenant model overrides. v1 is a single global route table.
