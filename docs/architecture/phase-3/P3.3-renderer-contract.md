## Context

The Generator page is a *generative UI surface* — the agent emits structured `GenNode` JSON and the renderer turns it into UI. This is a contract between server and client: the agent's emissions are valid `GenNode` shapes (P1.4 enforces this server-side), the renderer dispatches on `node.type` and renders.

The contract has three weak points today:

1. There is no in-app way to see what every `GenNode` type looks like. Field bug reports ("this looked weird") have no reference image.
2. Each component owns its own value reporting (`onChange(componentId, value)`), but the audit is informal.
3. Unknown types crash the renderer instead of degrading gracefully.

P3.3 hardens all three. Per [ADR-0003](../../decisions/0003-renderer-contract-in-app.md) the gallery lives **inside the app** at `/admin/genui-gallery`, not Storybook — no new dev dependency.

## Design

### `/admin/genui-gallery` route

A new admin-only page that renders every variant of every `GenNode` type from a JSONL fixture set:

```
client/src/pages/admin-genui-gallery.tsx
client/src/components/genui/gallery-fixtures.json
```

The fixture set is the **same JSONL** used by P2.4's eval harness (`tests/evals/fixtures/`), filtered to representative outputs. Single source of truth — drift between gallery and eval is impossible by construction.

Page layout (using existing CSS classes):

- **Type list** (left rail, `.sidebar-nav`): one entry per `GenNode` type, click to scroll.
- **Variant gallery** (main, `.tile`): for each variant, a heading and a rendered preview. Using `.table-card` for code/JSON view alongside.
- **Inspector** (right rail, `.panel`): the JSON shape of the currently focused component, copy-pasteable.

### Renderer audit

Walk every component in `client/src/components/genui/` and confirm:

1. Each accepts a strict `GenNode` variant (no `any`).
2. Each reports value via a uniform `onChange(componentId, value)` interface — refactored where it doesn't.
3. Each handles missing optional fields without crashing.
4. None silently mutates props.

The audit produces a small refactor branch; no new patterns introduced.

### Unknown type fallback

The router that maps `node.type` to component (`client/src/components/genui/Renderer.tsx` — to be created if not present) gets a default branch:

```tsx
function renderNode(node: GenNode): JSX.Element {
  switch (node.type) {
    case "Markdown": return <MarkdownNode {...node} />;
    case "QuestionSingleSelect": return <QuestionSingleSelect {...node} />;
    // ... 16 more cases
    default:
      return <ErrorCard
        title="Unsupported component"
        message={`Unknown type: ${(node as { type: string }).type}`}
      />;
  }
}
```

Today's renderer would crash on an unknown type. With this change, the user sees an `ErrorCard` instead, the issue is logged, and the session continues. `(node as { type: string }).type` is the type-narrow escape hatch — TypeScript guarantees the union is exhaustive at compile time, so the default branch only fires when the agent emits something not in the union (which P1.4 should already prevent at the server boundary, but defense-in-depth).

### Storybook-equivalent fixture coverage

Every `GenNode` variant must have at least one fixture in `gallery-fixtures.json`. CI check:

```ts
// scripts/verify-gallery-coverage.ts
import { GenNode } from "../client/src/components/genui/types";
import fixtures from "../client/src/components/genui/gallery-fixtures.json";

const allTypes = /* extract from GenNode union */;
const coveredTypes = new Set(fixtures.map(f => f.type));
const missing = allTypes.filter(t => !coveredTypes.has(t));
if (missing.length) {
  console.error("Missing gallery fixtures for:", missing);
  process.exit(1);
}
```

Wired into CI as part of the fast eval suite (P2.4).

### Documentation generation

A small script reads the `GenNode` Zod schema (P1.4) and produces a markdown reference:

```
docs/architecture/gennode-reference.md   (auto-generated, do not edit)
```

Regenerated on every CI run; if the file changes, CI fails until committed. This keeps the docs honest.

## Sequencing and dependencies

- **Before:** P1.4 (envelope schema) is the source of truth for the gallery; P2.4 (eval fixtures) provides the seed data.
- **After:** none.

## Exit criteria

1. `/admin/genui-gallery` renders all 17 (or 18 once `RagCitation` lands) variants from fixtures.
2. CI gallery coverage script enforces every `GenNode` type has at least one fixture.
3. Renderer audit complete; every component accepts a strict variant and reports via uniform `onChange`.
4. Unknown-type test: simulate an agent emitting `{ type: "FakeWidget" }` — renderer shows `ErrorCard`, no crash.
5. `gennode-reference.md` regenerates on CI; intentional drift fails the pipeline.

## Risks

| Risk | Mitigation |
|---|---|
| Gallery fixtures drift from real-world emissions | Fixtures are sourced from real eval traces; refresh quarterly. |
| Unknown-type fallback masks real bugs | Log every fallback hit; alarm if rate exceeds 0.1% of envelopes. |
| Renderer audit uncovers component churn | Treat as scope; expect 2–3 days of small refactors as part of P3.3 effort. |

## Out of scope

- Storybook (per ADR-0003).
- Visual regression testing (deferred; the gallery itself surfaces visual changes during MR review).
- Component documentation in JSDoc form (the reference doc is sufficient).
