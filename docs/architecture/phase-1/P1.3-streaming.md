# P1.3 — SSE Streaming, Resumable

| | |
|---|---|
| **Status** | not started |
| **Effort** | 1 week |
| **Owner** | TBD |
| **Depends on** | P1.1 (agent loop), P1.2 (tool catalog) |
| **Blocks** | P2.2 (async pipeline reuses the stream protocol) |

## Context

Generation latency for a full demo package today is 30–60 seconds. Without streaming the UX is a spinner that may as well be an outage. Field SAs on hotel and conference Wi-Fi will reload, click again, abandon — none of which today's app handles gracefully.

The architectural change is to stream events from the agent loop to the browser as they happen, with reconnect resumability so a transient network blip does not lose work.

## Design

### Protocol

Server-Sent Events (SSE), not WebSockets. Reasons:

- One-way (server → client) is what we need.
- HTTP/1.1 with `Connection: keep-alive` works through every CloudFront layer in the path; WebSockets need explicit configuration.
- Native browser `EventSource` API — no client library, no new dependency (constraint 5).

### Endpoint

```
GET /api/generator/agent/stream?sessionId=<id>&lastEventId=<n>
  Accept: text/event-stream
  Authorization: Bearer <Cognito JWT>
```

`lastEventId` is the resume cursor. On a fresh stream it is `0`. On reconnect the browser sends `Last-Event-ID` header automatically (via `EventSource`) and the server skips events `<= lastEventId`.

### Event types

```
event: prose_token
data: {"token": "Generating ", "step": 12}

event: component_committed
data: {"component": {"type": "InfraPreview", ...}, "step": 12}

event: tool_call_started
data: {"id": "tc_001", "name": "generateCFTemplate", "input": {...}}

event: tool_call_finished
data: {"id": "tc_001", "ok": true, "latencyMs": 4321}

event: progress_step_updated
data: {"id": "p_main", "stepIndex": 2, "status": "active"}

event: phase_changed
data: {"from": "gathering", "to": "generating"}

event: complete
data: {"sessionId": 42, "message": "...", "components": [...], "specSnapshot": {...}, "phase": "complete"}

event: error
data: {"kind": "validation"|"execution"|"budget", "message": "..."}
```

The `complete` event carries the **full F1 envelope** — see [ADR-0007](../../decisions/0007-streaming-preserves-envelope.md). Non-streaming clients can call the existing `POST /api/generator/agent` and ignore streaming entirely; both endpoints produce identical final envelopes.

### Server reorganization (`server/agent/`)

`runTurn` from P1.1 is refactored into an async generator:

```ts
export async function* runTurnStream(
  sessionId: number,
  userMessage: string,
  principal: Principal,
): AsyncGenerator<AgentEvent, FinalEnvelope, void> {
  // ... yields prose_token, tool_call_started, etc.
  // ... returns FinalEnvelope at the end
}
```

The non-streaming `runTurn` is implemented in terms of `runTurnStream`:

```ts
export async function runTurn(...) {
  let final: FinalEnvelope;
  for await (const event of runTurnStream(...)) {
    if (event.type === "complete") final = event.envelope;
  }
  return final;
}
```

This keeps the two endpoints in lockstep — one implementation, two transports.

### Buffering and resume

Events are persisted to a new Drizzle table:

```ts
export const agentEvents = pgTable("agent_events", {
  id: serial("id").primaryKey(),
  sessionId: integer("session_id").references(() => agentSessions.id).notNull(),
  turnIndex: integer("turn_index").notNull(),
  eventIndex: integer("event_index").notNull(),     // monotonic per session
  eventType: text("event_type").notNull(),
  payload: json("payload").notNull(),
  createdAt: timestamp("created_at").defaultNow().notNull(),
});
```

Index: `(sessionId, eventIndex)` for fast resume.

Reconnect logic:

```
GET /api/generator/agent/stream?sessionId=42, Last-Event-ID: 17
  → server queries agent_events WHERE sessionId=42 AND eventIndex > 17 ORDER BY eventIndex
  → replays buffered events
  → if turn still in flight, attaches to live stream
  → if turn completed during disconnect, replays through `complete` and closes
```

Events are retained for 24 hours per session, then garbage-collected by a cleanup job.

### Bedrock streaming

Today's `InvokeModelCommand` is replaced inside the loop with `InvokeModelWithResponseStream` (already in `@aws-sdk/client-bedrock-runtime`). The SDK delivers `chunk` events; each text delta becomes a `prose_token` event.

Tool-use blocks in the Bedrock stream are accumulated and emitted as a single `tool_call_started` once the block is complete (Bedrock's streaming format delivers tool calls atomically per block).

### Frontend changes (`client/src/services/agent.ts`, `client/src/pages/generator.tsx`)

`sendAgentTurn` gets a streaming variant:

```ts
export function sendAgentTurnStream(
  body: AgentRequest,
  handlers: {
    onProseToken: (token: string) => void;
    onComponent: (node: GenNode) => void;
    onToolStarted: (e: ToolStartedEvent) => void;
    onToolFinished: (e: ToolFinishedEvent) => void;
    onProgress: (e: ProgressEvent) => void;
    onPhase: (e: PhaseEvent) => void;
    onComplete: (env: FinalEnvelope) => void;
    onError: (e: ErrorEvent) => void;
  },
): { close: () => void };
```

Implementation uses native `EventSource` with `withCredentials: true` so the Cognito cookie/JWT flows through. (The existing `Authorization: Bearer` flow is preserved by appending the token as a query parameter on the SSE URL — the server validates it identically.)

`generator.tsx` uses the streaming variant; the existing non-streaming path remains as a fallback if `EventSource` is unavailable (effectively never on modern browsers).

### CloudFront considerations

CloudFront supports SSE if:

- Origin response sets `Content-Type: text/event-stream`.
- `Cache-Control: no-cache` is set.
- Compression is disabled for the response (gzipping a stream buffers it).

All three are set in the SSE handler. CloudFront caching policy for `/api/generator/agent/stream` is `CachingDisabled`.

### Auth on SSE

`EventSource` does not support custom headers, so we cannot send `Authorization: Bearer ...`. Two options:

1. **Cookie-based auth** — change Cognito to set an `httpOnly` cookie and rely on CloudFront forwarding it. Disruptive across the rest of the app.
2. **Token in query string** — append `?token=<jwt>` to the SSE URL; server validates with `aws-jwt-verify`.

We adopt **option 2** since it is local to this endpoint, does not affect the broader auth model (constraint 18), and the JWT is short-lived. The query parameter is logged in CloudFront access logs as a matter of operational hygiene; we filter it out of CloudWatch with a log-format adjustment.

| Constraint | How this complies |
|---|---|

| 6, 7 — framework lock | No new routers; new endpoint registered on existing Express app. |
| 8 — Drizzle + Neon | New `agent_events` table via Drizzle. |
| 9 — Bedrock only | `InvokeModelWithResponseStream` against Opus 4.6. |
| 15 — auth required | JWT validated on SSE endpoint via query parameter. |
| 18 — Cognito JWT verification | Same `aws-jwt-verify` path as other endpoints. |

## Sequencing and dependencies

- **Before:** P1.1, P1.2.
- **After:** P2.2 reuses `agent_events` for async-job resumption (the SA can close the laptop, reattach to the same `sessionId` later, and replay).

## Exit criteria

1. `EventSource` consumer in `generator.tsx` shows incremental prose, components committed in place, `ProgressTimeline` dot states updating.
2. Reconnect test: kill the network for 5 seconds during a 30s generation; the stream resumes from `Last-Event-ID` and the SA sees no missing events.
3. Latency-to-first-token ≤ 1.5 seconds (p50) on the production path.
4. CloudFront access log smoke test: SSE URLs do not appear with `?token=` (filtered) or appear only with token redacted.
5. Non-streaming `POST /api/generator/agent` produces an envelope equivalent to the SSE `complete` event for the same input (parity test on 20 prompts).

## Risks

| Risk | Mitigation |
|---|---|
| ALB / CloudFront idle timeout closes long-lived SSE connections | Ensure `keep-alive` heartbeat events sent every 15 seconds (`event: ping`). Confirm ALB idle timeout ≥ 120s. |
| Bedrock streaming chunk format changes | Pinned by `@aws-sdk/client-bedrock-runtime` version; covered by parity tests. |
| JWT in query parameter logged in unexpected places | Audit all log paths once before rollout; redact on output. |
| Resume buffer grows unbounded | Cleanup job (1/hour) deletes events for sessions older than 24h. |
| `EventSource` does not support POST | Resolved by accepting `sessionId` as a query parameter and posting the user message via `POST /api/generator/agent/turn` first, which returns a `streamUrl`. Two-step flow: POST to start, GET to stream. |

## Out of scope

- WebSocket fallback (not needed; SSE is universally supported).
- Bidirectional streaming (the model does not interrupt the user mid-turn).
- Resuming streams across `sessionId` (resume is within a session only).
