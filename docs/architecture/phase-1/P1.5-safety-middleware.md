## Context

DemoForge generates CloudFormation, application code, and learning modules that field SAs deploy in customer-adjacent environments. The generator is an LLM. Without deterministic post-generation scanning, the system can emit:

- CFN with public S3 buckets, open security groups, missing encryption, IAM wildcards.
- Code with hardcoded secrets, weak crypto, SQL injection patterns.
- Module text that references AWS services or APIs that do not exist.

Catching these *after* deployment is a customer-facing incident. Catching them *during* generation is a tool result with a clear remediation hint. P1.5 makes the second option the default.

## Design

### Toolchain

| Scanner | Targets | Source |
|---|---|---|
| `cloudformation:ValidateTemplate` | CFN syntax, basic semantics | Bedrock-region API call (Node-native, no install). |
| `cfn-lint` | CFN best practices, parameter consistency | Python — installed in Docker image. |
| `cfn-nag` | CFN security anti-patterns | Ruby — installed in Docker image. *Behind feature flag at first.* |
| `detect-secrets` | Hardcoded secrets in code emissions | Python — installed in Docker image. |
| In-house service-existence check | AWS service / API names that do not exist | Static catalog file (Bedrock service list). |

`cfn-nag` is gated on a feature flag for first 2 weeks because of false-positive noise; once tuned, it goes on for everyone.

### Dockerfile changes

Multi-stage build adds a Python + Ruby layer:

```dockerfile
# Existing builder stage unchanged.

FROM node:18-alpine AS runtime
RUN apk add --no-cache python3 py3-pip ruby ruby-dev
RUN pip3 install --break-system-packages cfn-lint==0.83.* detect-secrets==1.4.*
RUN gem install cfn-nag --version '~> 0.8'
# Existing COPY of dist/ unchanged.
```

Image size grows ~120MB. **Zero JS bundle impact** (constraint 5 governs frontend bundle, not backend image).

### Server organization

```
server/
  safety/
    index.ts                    # validate(kind, content, hints?) → SafetyReport
    cfn.ts                      # CFN scanners (validate + lint + nag)
    code.ts                     # detect-secrets
    modules.ts                  # service-existence check
    subprocess.ts               # safe spawn() with timeout, stderr capture
    catalogs/
      aws-services.json         # from Bedrock service list
```

### Safety report shape

```ts
export interface SafetyFinding {
  severity: "info" | "warn" | "error";
  rule: string;          // e.g. "W3045", "F101"
  location?: string;     // line number or resource path
  message: string;
  remediation?: string;
}

export interface SafetyReport {
  kind: "cfn" | "code" | "modules";
  passed: boolean;       // false if any severity === "error"
  findings: SafetyFinding[];
  scannedAt: Date;
}
```

### Integration point

Tools that emit risky content wrap their output through `validate()` before returning:

```ts
// server/tools/generateCFTemplate.ts
const template = await coreGenerator(input);
const report = await safety.validate("cfn", template);
if (!report.passed) {
  return {
    template,
    safetyReport: report,
    rejected: true,
  };
}
return { template, safetyReport: report };
```

The agent loop sees `rejected: true` in `tool_result` and (via a system-prompt instruction) re-invokes the tool with a remediation hint. The model gets one retry per resource. After that, the user sees an `ErrorCard` carrying the unresolved findings.

### Persistence

Safety findings are persisted to a new column on `agent_steps`:

```ts
safetyFindings: json("safety_findings").$type<SafetyFinding[]>(),
```

This makes "why did the model retry?" answerable in the trace.

### Subprocess hygiene (`server/safety/subprocess.ts`)

Spawning Python/Ruby tools in a Node process needs guardrails:

- **Timeout**: 10s per scan; kill the process group on timeout.
- **stdin-only**: write content to stdin, never to a temp file (avoids disk I/O races and tempfile cleanup bugs).
- **Limited stdout/stderr**: cap at 1 MB each; truncate beyond.
- **No shell**: `spawn(command, args, { shell: false })`.

### Service-existence check (`server/safety/modules.ts`)

The model occasionally hallucinates AWS APIs that do not exist (`aws ec2 imagine-instance`). The check:

1. Tokenize module text for `aws <word> <word>` and `<service>.<method>` patterns.
2. Look up `<service>` in `catalogs/aws-services.json`.
3. Look up the method in the service's API list (via the static catalog).
4. Surface unknown matches as `severity: "warn"` findings (not `error` — false positives common).

The catalog is generated nightly by a small script that pulls `aws --version`-equivalent lists; it does not require a network call at runtime.

## Constraint compliance

| Constraint | How this complies |
|---|---|
| 5 — no JS dependencies added | Python and Ruby tools live in the Docker image; no npm packages added. |
| 7 — Express + esbuild | Subprocess spawn is native Node; no framework change. |
| 8 — Drizzle + Neon | Findings persisted via Drizzle schema. |
| 9 — Bedrock only | `ValidateTemplate` is an AWS API, not a model call. |
| 10 — version bump | New Docker image content → version bump on every backend deploy. |

## Sequencing and dependencies

- **Before:** P1.2 (tools wrap their output through `safety.validate()`).
- **After:** P2.1 (tracing includes safety findings in the timeline view).

## Exit criteria

1. 20-template corpus of known-bad CFN: every one is caught (≥ 1 `severity: error` finding).
2. 5 known-bad code emissions (hardcoded `AKIA...`, etc.): every one is caught by `detect-secrets`.
3. False-positive rate on a 50-template corpus of known-good CFN: ≤ 5% with `cfn-lint` only; document the rate with `cfn-nag` enabled before flipping the flag.
4. Subprocess timeout test: a malicious 100MB CFN template is rejected within 10s.
5. Module text containing a hallucinated AWS service name surfaces as a `warn` finding.

## Risks

| Risk | Mitigation |
|---|---|
| `cfn-nag` false-positive noise drowns real findings | Feature flag; tune rules before enabling for all users. Document tuning decisions in this file. |
| Subprocess fork limits on small ECS tasks under load | Cap concurrent scans at `MAX_CPU_COUNT - 1`; queue beyond. |
| Static AWS service catalog goes stale | Regenerate nightly; alarm on > 7 days since last refresh. |
| `detect-secrets` plugin set diverges from upstream | Pin `detect-secrets` version explicitly; bump quarterly with eval check. |

## Out of scope

- Runtime IAM permission analysis (would need `cfn-iam-policy-validator` — defer to Phase 2).
- License scanning of generated code (defer; field-tool scope is internal).
- Bandit/Semgrep code scanning beyond secrets (defer; secret scanning catches the majority of real issues for our code shapes).
