## Context

Today, generation is a single Bedrock call that asks Opus 4.6 to produce CFN, code, schema, modules, and cost estimates inside one response. The model is implicitly trusted to emit valid YAML, valid SQL, valid Python, and valid pricing math — all in one pass, with no validation, retries, or composition.

The architectural shift is to make the model an *orchestrator*, not a *generator-of-everything*. Deterministic code does the heavy lifting via typed tools; the model decides which tool to call and with what arguments. This is the single highest-leverage change in the plan because it converts "trust the model" into "constrain the model to a small set of well-tested operations."

The existing logic in `server/templateGenerator.ts`, `server/agent.ts`, and the cost estimator is **kept**, not thrown away. Each becomes a tool implementation.

## Design

### Directory layout

```
server/
  tools/
    index.ts                    # registry: name → { spec, execute }
    types.ts                    # ToolSpec, ToolInput, ToolResult, Principal
    lookupExtensions.ts         # pure function over static catalog
    searchPriorDemos.ts         # queries demoRequests; replaced by RAG in P3.1
    estimateInfraCost.ts        # extracted from existing logic
    generateCFTemplate.ts       # wraps templateGenerator.ts
    generateSchema.ts           # wraps existing schema generator
    generateAppCode.ts          # wraps existing code generator
    generateModules.ts          # wraps existing module generator
```

### Tool contract (`server/tools/types.ts`)

```ts
import { z } from "zod";

export interface Principal {
  userId: string;          // Cognito sub
  email: string;
  isAdmin: boolean;
}

export interface ToolSpec<I extends z.ZodTypeAny, O extends z.ZodTypeAny> {
  name: string;
  description: string;
  inputSchema: I;
  outputSchema: O;
  execute(principal: Principal, input: z.infer<I>): Promise<z.infer<O>>;
}

export interface ToolError {
  kind: "validation" | "execution" | "permission" | "timeout";
  message: string;
  retryable: boolean;
}
```

### Bedrock tool-use format

At server boot, the registry produces Bedrock-compatible tool definitions:

```ts
const tools = registry.all().map(t => ({
  name: t.name,
  description: t.description,
  input_schema: zodToJsonSchema(t.inputSchema),
}));
```

These pass to `InvokeModelCommand` body as `tools: [...]`. The model emits `tool_use` blocks; the loop (`P1.1`) executes them and appends `tool_result` blocks to history.

### Validation and retry

Each tool call goes through:

1. **Input validation** against `inputSchema`. On failure → return `ToolError(kind=validation)`. The agent loop appends this as a `tool_result` so the model can correct in the next iteration. **Single retry**, then `ErrorCard`.
2. **Permission check** in `execute()` — the tool itself enforces ACL using `principal`. Anything user A cannot see is filtered at query time, regardless of what the model asks. (Full treatment in P1.6.)
3. **Output validation** against `outputSchema`. Failure here is a tool bug, not a model bug — log loudly and return `ToolError(kind=execution)`.

### Per-tool circuit breaker

A simple counter per tool: if `> 5` consecutive failures in a 60-second window, the tool is taken out of the catalog for the next minute and tool calls return `ToolError(kind=timeout)`. Prevents runaway loops when (e.g.) Bedrock pricing API is down.

### Refactor of `/api/generator/agent`

Today's monolithic prompt (`agentRoutes.ts:342-347`) is replaced with:

- **System prompt** — describes the orchestrator role and the envelope contract.
- **Tool defs** — passed in `tools` parameter; not embedded in prompt.
- **Structured output** — Bedrock tool-use guarantees valid JSON for tool calls; the final envelope is validated against the `GenNode` union.

The system prompt shrinks from ~600 chars to ~300 chars. The model is told *what to do*, not *how to format*.

## Constraint compliance

| Constraint | How this complies |
|---|---|
| 5 — no new dependencies | Zod is already a dependency. `zod-to-json-schema` is the only candidate addition; instead, write a small in-house converter (~30 LOC) and avoid the dep. |
| 8 — Drizzle + Neon | Tools that read DB use Drizzle queries, no raw SQL. |
| 9 — Bedrock only | All model calls go through `bedrock.invoke()` (P1.1). |
| 15, 16 — auth | `principal` threaded into every `execute()` call. Admin tools require `principal.isAdmin`. |
| 20 — structured envelope | Final emission still `{message, components, specSnapshot, phase}`; tool calls happen inside the loop, not in the envelope. |
| 21 — fixed `GenNode` types | Output validation against the union; new types follow [ADR-0010](../../decisions/0010-gennode-gated-process.md). |

## Sequencing and dependencies

- **Before:** P1.1 (agent loop is required to execute tools in iterations).
- **After:** P1.3 streams `tool_call_started` / `tool_call_finished` events. P1.5 wraps tool outputs with safety scanners. P1.6 enforces per-tool ACL. P3.1 adds RAG tools to the catalog.

## Exit criteria

1. All eight tools registered; `registry.all()` returns eight specs.
2. Bedrock tool-use API drives generation — verified by inspecting `agent_steps.tool_calls` for representative sessions.
3. Parity test: 20 representative prompts produce envelopes equivalent to today (semantic equivalence on `specSnapshot`, structural equivalence on `components`).
4. Single-retry behavior verified: a known-bad input produces one validation error in `agent_steps.tool_results`, then a corrected call.
5. Circuit breaker test: forced 6 consecutive failures take the tool offline; recovery after 60s.
6. The system prompt is ≤ 400 characters and contains no JSON schema definitions (those are now in `tools` parameter).

## Risks

| Risk | Mitigation |
|---|---|
| Existing generators (`templateGenerator.ts` etc.) are tightly coupled to today's monolithic flow | Extract them via an adapter layer before refactoring callers; ship the extraction in a separate MR. |
| Bedrock tool-use payload size limit on long histories | Implement history truncation (keep first turn + last N + summary of older steps). Defer to first time a session hits the limit. |
| `zod-to-json-schema` in-house converter incomplete | Cover only the Zod types we use (string, number, boolean, object, array, enum, optional, nullable). Throw on unsupported types so we catch gaps in tests. |
| Tool implementations have side effects (writes to DB) that retries duplicate | Add idempotency keys per tool call (hash of `(name, normalized input, sessionId, turnIndex)`). |

## Out of scope

- RAG-backed retrieval tools (P3.1).
- Multi-model tool routing (P3.2).
- Tool result caching (P2.3).
- Storybook-style tool catalog browser (use `/admin/genui-gallery` from P3.3 instead per [ADR-0003](../../decisions/0003-renderer-contract-in-app.md)).
