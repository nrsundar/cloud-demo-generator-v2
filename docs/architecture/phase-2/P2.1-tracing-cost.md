# P2.1 — Per-Turn Tracing + Cost Accounting

| | |
|---|---|
| **Status** | not started |
| **Effort** | 1 week |
| **Owner** | TBD |
| **Depends on** | P1.1, P1.2 |
| **Blocks** | P2.2 (debugging async failures), P2.4 (eval scoring uses traces), P3.4 (drift detection) |

## Context

Standard APM tools were not designed for stochastic systems. When a field SA reports "the demo was wrong," the support engineer needs to reconstruct: every model call, every tool call, every retrieval, every token count, every latency, every input/output payload, linked into a single span tree per turn.

P2.1 builds that visibility in-house ([ADR-0001](../../decisions/0001-tracing-stays-in-house.md)) — no LangFuse, no LangSmith, no SaaS. Tables in the existing Neon DB; an admin tab in the existing dashboard using the existing CSS classes. It also covers cost accounting: per-user, per-team, per-model breakdowns.

## Design

### Schema additions

```ts
// shared/schema.ts

export const agentTraces = pgTable("agent_traces", {
  id: serial("id").primaryKey(),
  sessionId: integer("session_id").references(() => agentSessions.id).notNull(),
  turnIndex: integer("turn_index").notNull(),
  startedAt: timestamp("started_at").defaultNow().notNull(),
  endedAt: timestamp("ended_at"),
  status: text("status").notNull().default("running"),  // 'running' | 'ok' | 'error' | 'budget_exceeded'
  totalTokensIn: integer("total_tokens_in").default(0),
  totalTokensOut: integer("total_tokens_out").default(0),
  totalLatencyMs: integer("total_latency_ms").default(0),
  estCostUsd: text("est_cost_usd"),                     // 6 decimal places, stored as text
  errorKind: text("error_kind"),
  errorMessage: text("error_message"),
});

export const agentSpans = pgTable("agent_spans", {
  id: serial("id").primaryKey(),
  traceId: integer("trace_id").references(() => agentTraces.id).notNull(),
  parentSpanId: integer("parent_span_id"),               // self-reference; nullable for root
  kind: text("kind").notNull(),                          // 'model' | 'tool' | 'retrieval' | 'safety'
  name: text("name").notNull(),                          // e.g. 'bedrock.invoke' or 'generateCFTemplate'
  startedAt: timestamp("started_at").defaultNow().notNull(),
  endedAt: timestamp("ended_at"),
  durationMs: integer("duration_ms"),
  input: json("input"),
  output: json("output"),
  error: json("error"),
  tokensIn: integer("tokens_in"),
  tokensOut: integer("tokens_out"),
  modelId: text("model_id"),
  cacheHit: text("cache_hit"),                           // 'prompt' | 'tool_result' | null
  costUsd: text("cost_usd"),
});
```

Indexes: `(sessionId, turnIndex)` on traces; `(traceId, startedAt)` on spans.

### Span schema

A turn produces a tree:

```
trace
└─ span(kind='model', name='bedrock.invoke')
   ├─ span(kind='tool', name='generateCFTemplate')
   │  ├─ span(kind='safety', name='cfn-lint')
   │  └─ span(kind='safety', name='cfn-nag')
   ├─ span(kind='tool', name='estimateInfraCost')
   └─ span(kind='retrieval', name='searchPriorDemos')      // when P3.1 lands
└─ span(kind='model', name='bedrock.invoke')              // second iteration
```

### Instrumentation surface

A small helper in `server/agent/trace.ts`:

```ts
export async function withSpan<T>(
  trace: TraceHandle,
  parent: SpanHandle | null,
  kind: SpanKind,
  name: string,
  attrs: Partial<SpanRow>,
  fn: () => Promise<T>,
): Promise<T> {
  const span = await openSpan(trace, parent, kind, name, attrs);
  try {
    const result = await fn();
    await closeSpan(span, { output: result });
    return result;
  } catch (err) {
    await closeSpan(span, { error: serializeError(err) });
    throw err;
  }
}
```

Used pervasively:

```ts
// inside the agent loop
await withSpan(trace, null, "model", "bedrock.invoke", { modelId }, async () => {
  return await bedrock.invoke(...);
});

// inside a tool
await withSpan(trace, parentSpan, "tool", this.name, { input }, async () => {
  return await this.coreImpl(input);
});
```

### Cost accounting

Bedrock returns `usage.input_tokens` and `usage.output_tokens` per call. A static price table maps `modelId` → `(inputCostPerMillion, outputCostPerMillion)`:

```ts
// server/agent/pricing.ts
export const PRICING: Record<string, { in: number; out: number }> = {
  "us.anthropic.claude-opus-4-6-v1": { in: 15.00, out: 75.00 },
  // future entries gated on ADR-0011 (multi-model routing)
};

export function estimateCost(modelId: string, tokensIn: number, tokensOut: number): string {
  const p = PRICING[modelId];
  const usd = (tokensIn / 1_000_000) * p.in + (tokensOut / 1_000_000) * p.out;
  return usd.toFixed(6);
}
```

Costs roll up: span cost → trace cost → daily totals (computed on demand by the admin UI; no precomputed rollup table for v1).

### Admin UI

New tab in the existing Admin Dashboard, "Traces":

- **List view** — recent traces, sortable by user, latency, token count, cost. Uses `.table-card` and `.tbl` classes.
- **Detail view** — span timeline (visual: stacked horizontal bars, durations to scale; uses `.tile` and `.badge-status` classes for status colors).
- **Filters** — by user, model, status, error kind, date range.
- **Cost view** — per-user / per-team / per-model rollups for the last 1d / 7d / 30d. Uses `.tiles` for summary cards, `.tbl` for breakdowns.

No new design tokens; no charts library (line chart for cost-over-time uses inline SVG ~50 LOC).

### API endpoints

```
GET /api/admin/traces?user=&model=&status=&from=&to=&limit=
GET /api/admin/traces/:id                 // includes spans
GET /api/admin/traces/cost-rollup?groupBy=user|team|model&from=&to=
```

All admin-only (`requireAdmin`).

### Sampling strategy

Every turn is fully traced. (No sampling — at field-tool scale, full traces fit comfortably in Neon. Revisit if `agent_spans` grows beyond ~100M rows.)

Long-tail span retention: 90 days. Traces older than 90 days are aggregated into daily rollups and the spans deleted. Implemented as a daily cleanup job.

### What this does not include

- No OTel exporter. We can add one later if needed; for now in-house schema is simpler.
- No span ingestion from outside our process (no distributed tracing across services because we don't have services).

## Sequencing and dependencies

- **Before:** P1.1 (sessions exist), P1.2 (tools exist to instrument).
- **After:** P2.2 — async-job failures show up as traces in error state, debuggable from the same UI. P2.4 — eval runs are traced as well. P3.4 — drift detection reads from `agent_traces`.

## Exit criteria

1. Every turn produces exactly one `agent_traces` row and ≥ 1 `agent_spans` row.
2. Trace detail page renders for a representative session with timeline visible.
3. Cost-rollup endpoint produces totals matching hand-computed costs for a corpus of 50 traces (within 0.01 USD).
4. Admin can answer "what happened on session X turn Y" within 60 seconds of receiving the report.
5. 90-day cleanup job runs without errors on a mock dataset.

## Risks

| Risk | Mitigation |
|---|---|
| Span writes per turn introduce latency | Spans flushed asynchronously to a small in-memory buffer; flush every 250ms or on turn end. Buffered fail mode: write to a fallback table on disk if DB unreachable. |
| Cost table drifts from actual Bedrock pricing | Document review cadence (quarterly); alarm if the price table is more than 90 days old. |
| Trace detail JSON payloads bloat row size | Cap `input` and `output` JSON at 256 KB per span; truncate with marker beyond that. |
| Admin UI becomes a debugging crutch nobody else can use | Field SAs should also see their own traces (read-only). Add a `/my-traces` route in P2.1 polish work. |

## Out of scope

- LangFuse / LangSmith / Helicone integration — see ADR-0001.
- Distributed tracing (we are a single service).
- Real-time trace streaming to admin UI (refresh on demand is sufficient).
