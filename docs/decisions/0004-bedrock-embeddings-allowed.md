# ADR-0004 — Bedrock embeddings allowed under constraint 9

**Status:** accepted (2026-05-07)
**Decided by:** project owner
**Supersedes:** none

## Context

`CONSTRAINTS.md` constraint 9 reads: *"AI: AWS Bedrock only — Model: us.anthropic.claude-opus-4-6-v1. No OpenAI, no direct Anthropic API."*

Phase 2 caching and Phase 3 RAG require text embeddings (vector representations of documents). Embeddings are not generated by Opus 4.6 — they are produced by dedicated embedding models. The available options on Bedrock include `amazon.titan-embed-text-v2:0` and `cohere.embed-english-v3` / `cohere.embed-multilingual-v3`.

Strict reading of constraint 9 would disallow embedding models because they are not the named generation model. That makes RAG impossible.

## Decision

Constraint 9 governs **generation** models. Embeddings are a different modality and are explicitly allowed under this ADR, provided they are accessed through Bedrock (not through a separate provider).

Default embedding model: `amazon.titan-embed-text-v2:0` (1024 dim). Fallback: `cohere.embed-multilingual-v3` (1024 dim) if Titan is unavailable in `us-east-2`.

## Consequences

**Easier:**

- RAG is unblocked.
- Embedding cost is dramatically lower than generation cost (Titan v2: ~$0.02 per million tokens).
- All AI traffic still flows through a single AWS service (Bedrock).
- No new SDK needed; `@aws-sdk/client-bedrock-runtime` covers both `InvokeModel` and embeddings via the same `InvokeModelCommand` shape.

**Harder:**

- We must update constraint 9 in `CONSTRAINTS.md` to reflect this scoping. The text becomes: *"AI generation: AWS Bedrock only, Opus 4.6 default. Embeddings via Bedrock (Titan or Cohere). No OpenAI, no direct Anthropic API."*
- Future contributors might assume the relaxation extends to other modalities. It does not — re-rankers, vision models, anything else require a fresh ADR.

## Alternatives considered

- **Strict reading: no embeddings, no RAG.** Eliminates a core Phase 3 feature. Rejected.
- **Bedrock + Anthropic embeddings.** Anthropic does not offer first-class embeddings; rejected.
- **Self-hosted embedding model on ECS.** Adds compute cost, model management, and a non-Bedrock path. Rejected — operational overhead not justified.
